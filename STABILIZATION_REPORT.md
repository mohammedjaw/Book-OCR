# Book-OCR stabilization report

Completed September 14, 2026. This pass preserves the existing application and its pre-existing uncommitted work. Verification used disposable databases, PDFs, and synthetic secrets. The real library and saved keys were not opened for modification or used for OCR.

1. **Root causes found.** Live polling referenced undefined `progressText`/`workerText` variables and stopped after errors. Retry-failed indexed a one-element tuple as if it had two elements. Start included failed pages automatically. Generic `RESOURCE_EXHAUSTED` was treated as daily quota; key failures became failed pages. The worker used cumulative quota failures to stop an entire job. The key pool was missing, counters incremented twice, and secret updates could race. Recovery ran during Start and ignored recently interrupted pages. SQLite connections were not explicitly closed. Settings had two conflicting persistence sources. Package import trusted UUID-derived paths, did not verify actual PDF page count, and indexed outside the import transaction. Delete raced active OCR and unlinked an unrestricted path. Reader jump navigation used the wrong parameter. Windows export temporary files remained open.

2. **Exact files changed in this pass.** Backend: `app/book_manager.py`, `app/database.py`, `app/export_service.py`, `app/gemini_key_manager.py`, `app/lifecycle.py`, `app/ocr_service.py`, `app/ocr_worker.py`, `app/package_service.py`, `app/routes/books.py`, `app/routes/home.py`, `app/routes/search.py`, `app/routes/settings.py`, `app/routes/transfer.py`, `app/search_service.py`, `app/secrets.py`, `app/ui.py`, `main.py`. UI: `static/css/style.css`, `static/js/book-status.js`, `templates/base.html`, `templates/book_detail.html`, `templates/delete_book.html`, `templates/full_text.html`, `templates/page_detail.html`, `templates/search.html`, `templates/settings.html`. Verification/documentation: `test_gemini_ocr.py`, `tests/test_stabilization.py`, `tests/test_polling.cjs`, `tests/browser_fixture.py`, `README.md`, `STABILIZATION_REPORT.md`. Existing changes in `requirements.txt`, `templates/pages.html`, and `app/i18n.py` were retained without additional functional edits.

3. **OCR state machine.** Conditional SQL claims only pending pages. Completed pages cannot be reclaimed. Text and FTS entries commit together. Page-level permanent errors become failed; transient errors have bounded retries. Key unavailability and interrupted scheduling return claims to pending. Ordinary Start processes pending pages; Retry operates only on the eligible failed subset. Worker state distinguishes running, pausing, paused, completed, stopped, unavailable keys, and application errors.

4. **Live refresh.** Explicit DOM references replace implicit globals. Polls run every three seconds during work, fifteen seconds while idle/hidden, and back off after network errors. Requests have a timeout and do not overlap. Counts, progress, worker message, buttons, and export availability update together. Actions submit without reloading. Visibility changes fetch current state. Browser verification observed 0/8 become 8/8 and exports appear without refresh.

5. **Retry/backoff.** Up to four attempts for timeout/network errors, temporary 429, and 500/502/503/504 errors. Delays start around 4, 8, and 16 seconds plus jitter; numeric Retry-After and recognized provider retry hints extend the delay (bounded to one hour). SDK automatic retries are disabled so the app owns pacing and counters. Each generation call has a 120-second timeout. Permanent requests are not automatically retried. Raw provider messages are not persisted.

6. **Request pacing.** New databases default to two concurrent pages, configurable 1–5. Existing saved concurrency is preserved. A shared scheduler spaces request starts at least two seconds apart across jobs, without sleeping after successful requests. Cooling keys wait independently. PyMuPDF operations used for OCR, upload validation, and import validation are serialized.

7. **Multi-key behavior.** Single mode uses only the manually active key. Pool mode uses only explicitly checked saved keys. A lock protects selection, cooldowns, counters, and secret-store read/modify/write operations. Available keys rotate by scheduling history. Pages have one active claim, never parallel requests to several keys for the same page.

8. **Quota behavior.** Explicit daily indicators disable the affected key for the Los Angeles quota day. Generic 429/resource exhaustion produces temporary cooldown. Invalid keys are excluded. Remaining selected keys continue. If none remain, the worker drains and pauses with a clear message; unprocessed pages remain pending. Day rollover clears daily exhaustion and counters. An outcome from yesterday cannot exhaust the new day's key or inflate today's success/failure counts. Resume is explicit.

9. **Settings/theme.** Database preferences are authoritative on every rendered page. Light/Dark/System and language survive save/reload/reinitialization. Font, size, line spacing, model, thinking, concurrency, active key, mode, and pool persist. Omitted fields retain their previous values. Preview changes do not write browser-local preferences. Forms are separate, not nested. Core settings, worker controls, and deletion UI have Arabic, English, and Persian labels.

10. **Portable package validation.** ZIP contains exactly `manifest.json`, `pages.json`, and `original.pdf`, with level-9 DEFLATE and byte-preserved PDF. Export excludes internal paths, database, secrets, and rendered images. Import checks exact member allowlist, duplicates, encrypted/symlink entries, bounded sizes, version/type, canonical UUID, title/filename, complete page texts, ordering/count, hash, and actual PDF count. PDF copy, metadata, pages, and search entries share the import transaction boundary with file cleanup on failure. Injected indexing failure rolled back records and removed the copied PDF. Word/JSON temporary file handles now close before use on Windows.

11. **Full-page/full-book views.** Physical previous/next links stop at book boundaries; page-jump uses the reader's actual query parameter. OCR text is untruncated and escaped safely. Full-book mode presents twenty physical pages per segment with clear boundaries and original-PDF links. Typography honors saved reader settings. The PDF iframe uses the same physical page number.

12. **Delete Book.** Separate localized confirmation displays the title and requires a checked confirmation. Active OCR is paused and must drain before deletion. Scheduler locking closes Start/Delete races. Deletion rejects paths outside managed PDF storage and PDFs referenced by another book. It removes page indexes, page records, book record, and stored PDF; exported packages elsewhere are untouched. A staged rename can be restored on database failure, and startup restores referenced PDFs after interrupted deletion.

13. **Search/index behavior.** Stored OCR text remains unchanged. Arabic normalization is applied only to derived indexes and flexible query text. FTS queries quote user text to prevent syntax errors; normalization-only queries do not crash highlighting. Import and OCR index updates are atomic. Search navigation fetches identifiers rather than thousands of full texts. Results retain page/PDF links and selected search mode. List/status pages avoid loading all OCR text.

14. **Restart recovery.** FastAPI lifespan acquires a library process lock before initialization/recovery. A second server cannot recover another worker's claims. Startup returns all interrupted processing rows to pending and leaves completed text intact; paused jobs do not auto-start. Graceful shutdown stops scheduling and waits for active workers. Migration only adds the error-kind column, index, and missing defaults. Connections close at context exit with a 30-second SQLite lock timeout.

15. **Security checks.** UI exposes only masked key suffixes and whitelisted metadata. New error handling records error categories instead of provider payloads. Secrets are saved by locked atomic replacement. Portable packages use an explicit metadata allowlist. Imported OCR text is HTML-escaped in readers. Automated tests block Gemini client creation. The manual test's exception output is redacted to an error category.

16. **Tests executed.** `python -m unittest discover -s tests -v`: **25 passed**, including an accelerated 463-page run with exactly one processing invocation per page and concurrency at most five. Coverage includes completion/counters, pause/resume, failed-subset retry, temporary 429, timeout, 500/503, permanent errors, single key, pool failover, invalid keys, all keys unavailable, pacing/cooldown, concurrent counters, quota rollover, settings and form structure, package roundtrip/malformed inputs/transaction rollback, exact/flexible search, reader/PDF links, all exports, deletion isolation/path safety/crash restoration, and startup locking/recovery. `node tests/test_polling.cjs`: passed active-state, buttons, polling failure recovery, completion, and idle pacing assertions. Python compile checks and `git diff --check`: passed. Browser tests used a disposable local server: live completion, pause/drain/resume, navigation while OCR continues, saved themes, Arabic/Persian RTL and English LTR, 390px and 900px layouts, full-book view and reader. A pagination contrast defect found visually was fixed; computed contrast and no horizontal overflow were verified. Dependency deprecation warnings remain but did not fail tests.

17. **Remaining limitations.** No real 1–2 hour Gemini soak test was performed; 463-page verification was accelerated and mocked. Google project-level quota may be shared across keys. The application deliberately supports one server process per library, and concurrency is configured per book while pacing is shared. Native PDF iframe behavior depends on the browser's PDF viewer. Some pre-existing secondary-page labels remain Arabic. Full-book mode is segmented; search-result next/previous navigation retains the existing 10,000-result cap. Startup still rebuilds the derived FTS index, which can take time for a very large library. Import caps are 2 GiB PDF and 256 MiB page JSON. A hard crash after delete's database commit but before removing its staged file can leave an unreferenced `.pdf.deleting` file; it is not automatically deleted to avoid unsafe cleanup. Historical counters already inflated by the old implementation are not retroactively guessed or corrected; the next quota-day reset starts clean totals.

18. **Existing OCR text.** No existing successful OCR text was rewritten or deleted. All automated and browser writes targeted disposable fixtures. The real application will apply its additive migration/recovery at the next normal startup.

19. **Gemini calls.** No Gemini generation calls were made during automated tests, browser checks, or this stabilization pass. All generated responses were synthetic. The manual live-generation script was not run.

20. **Git.** No commit or push was performed. Pre-existing uncommitted work remains in place.

To use the changes, restart the local server from the project directory with `uvicorn main:app --host 127.0.0.1 --port 8000`, then review Settings and resume the desired book. Avoid development auto-reload during unattended OCR.
